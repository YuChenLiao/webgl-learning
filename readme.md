# 跟着大肥鱼老师（DeepSeek）学 WebGL

> 不讲玄学，从 GPU 管线和 GLSL 着色器讲起。

这个仓库是我跟着**大肥鱼老师**（DeepSeek）学 WebGL 的过程记录。它由两部分组成：一份从渲染管线讲到实战的**学习手册**，和一个把手册里的案例**亲手重写成工程化模块**的代码目录。

一句话定位：**WebGL 是 GPU 的遥控器，three.js 是坐在遥控器前面的导演。** 先把遥控器摸熟，再看导演是怎么用它的。

版本基准：WebGL 2.0 / GLSL ES 3.00，`gl-matrix` 3.4.4，对照 three.js r186。

## L3：光照球体与轨道相机

L1和L2比较简单，直接复制代码即可运行观察，所以直接跳到L3

对应手册第 5 章的 L3 案例，区别在于：手册里为了便于阅读，给的是**单文件版**（HTML 里内联全部 JS）；这里我按职责拆成了模块，并顺手做了几处工程化处理。

| 文件 | 职责 |
| --- | --- |
| `L3/index.html` | 页面骨架，`importmap` 从 CDN 引入 `gl-matrix`，挂载 canvas |
| `L3/main.js` | 主流程：上下文、视口与 DPR、渲染状态、几何构建、交错 VBO + VAO、程序化棋盘纹理、uniform 赋值、渲染循环 |
| `L3/gl/gl.js` | GLSL ES 3.00 的顶点与片元着色器源码（模板字符串导出） |
| `L3/utils/ball.js` | 程序化生成球体几何：位置、法线、UV、索引 |
| `L3/utils/camera.js` | `OrbitCamera` 轨道相机：pointer 事件拖拽 + 滚轮指数缩放 |
| `L3/compile/compile.js` | 着色器编译与 program 链接，失败时抛错并清理 |

几个值得记住的数：

- 球体取 64 段经线 × 40 段纬线，顶点数 `(64+1) × (40+1) = 2665`，索引数 `64 × 40 × 6 = 15360`。2665 < 65535，所以索引用 `Uint16` 就够。
- 顶点数据交错成一个数组 `[x, y, z, nx, ny, nz, u, v]`，每顶点 8 个 float，stride 32 字节，三个属性的字节偏移分别是 `0 / 12 / 24`。
- 属性位置用 `getAttribLocation` 动态查询，不硬编码 `0/1/2`，避免链接器重排后错位。
- 光照是逐像素 Blinn-Phong：漫反射 + 高光（指数 96）+ 距离衰减 + 冷色边缘光 + 环境光，最后做 `pow(color, 1/2.2)` 伽马编码输出。
- 纹理是程序化生成的棋盘格（免外部图片依赖），额外画了两条彩色标记，方便观察球体旋转与 UV 分布；球面横向用了 `REPEAT`，纵向用 `CLAMP_TO_EDGE`。

## 怎么跑起来

**必须通过 HTTP 打开，不能双击 `index.html`。** 因为 `index.html` 里用了 `type="module"`，并通过 `importmap` 从 jsdelivr CDN 拉 `gl-matrix`，`file://` 协议下会被同源策略拒绝。

在仓库根目录启动一个静态服务器：

```bash
npx serve .
# 或
python -m http.server 8080
```

然后访问 `http://localhost:3000/L3/`（`serve` 默认端口 3000）或 `http://localhost:8080/L3/`（Python）。也可以先 `cd L3` 再启动，那样访问根路径即可。

页面操作：**拖拽鼠标环绕观察，滚轮拉近拉远。** 相机极角被限制在 `(0.02, π-0.02)` 之间，距离被限制在 `1.6 ~ 30`，所以不会翻转、也不会穿进球体内部。

> 离线环境提醒：唯一的外部依赖是 `gl-matrix`，走的是 CDN。需要在无网环境开发时，把它换成本地文件路径即可，其余代码零依赖。

## 跑通后该做的实验

光跑出来不算学会，能**预测**调参后的画面变化才算。手册 L3 章节给了三处改动，值得逐个验证：

1. 把片元着色器里的高光指数 `96.0` 改成 `8.0`：高光会变得又大又糊，材质看起来像塑料。
2. 把 `uAmbientColor` 从 `0.06` 提到 `0.3`：暗部变灰、立体感下降，能直观感受环境光在"偷"对比度。
3. 把片元输出改成 `outColor = vec4(vUv, 0.0, 1.0);`：直接看到 UV 在球面上的分布，这是排查纹理问题最直观的一招。

## 面试准备

作为一个以「面试准备」为顶层目录的项目，手册第 8 章的 24 道题是这条学习路径的落点。它的难度分档是：**基础**（必答不丢分）、**进阶**（区分度所在）、**原理与场景**（决定评级）。

手册给的临场一句话准备：WebGL 的考察核心是**"你能不能说清 GPU 在做什么"**。把渲染管线的四段（顶点处理 → 光栅化 → 片元处理 → 逐片元操作）、两次"除以 w"（透视除法）、一次"插值"（varying 传递）串起来讲，基本可以支撑一场 40 分钟的深聊。

配合第 9 章的自检表自查，能定位**黑屏、纹理全黑、深度错乱**这三类典型故障是底线要求。
